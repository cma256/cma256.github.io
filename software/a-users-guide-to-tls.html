A User's Guide to TLS

Published on Thursday, November 5, 2026 - 8:00 PM CST

TLS is a protocol that I'm willing to bet every programmer on Earth has applied at one point or another. TLS stands for "Transport Layer Security". Because I've seen some fear, confusion, and mistruths around using TLS in Python, I wanted to demonstrate both how easy it is to use (you're already doing it) and how obvious it is (you're already doing it).

First, TLS is just a protocol which can be layered within a TCP stream. When you make a TLS request you do not in any way interfere with TCP or HTTP or your application layer protocol. These protocol layers are fully decoupled from one another (I'm overstating this point as this is an introductory article). If we were to model it as a function call chain it would look like this: tcp(tls(http(bytes))).

Let's see an example TLS client:

import socket
import ssl

# spooky context instance
ctx = ssl.create_default_context()

with socket.create_connection(("www.python.org", 443)) as sock:
    with ctx.wrap_socket(sock, server_hostname="www.python.org") as tls:
        tls.sendall(b"hello")
        data = tls.recv(4096)

Seven lines of code to implement a TLS client. But, you may say, look at all this crazy code you had to call to make it work. What's the overhead of all this? Let's consider another example:

import requests; requests.get("https://www.python.org")

The protocol prefix implies this request is encrypted (https), but where is our SSL import? The encryption, though cleverly hidden behind a few method calls, is right in front of you. Follow the "requests.get" method to its source and you eventually find:

return ssl_context.wrap_socket(sock, server_hostname=server_hostname)

It's at this point you unlock the secrets of the universe. It's code all the way down. There is no magic. You have been calling this code all along; you just never noticed.

The big question people now have is how do I define a server? The pattern established by the client holds there as well. The bigger question people ask is how do I load balance between multiple TLS-protected TCP servers?

You use a load balancer. Load balancers, like nginx or HAProxy, are described as "Layer 4" reverse proxies. They do not care about your application-layer protocol. They speak TCP and TLS. They can terminate TLS if configured and will forward plaintext TCP bytes to your application server.

I'll leave a TCP server as an exercise to the reader. You don't need my help to prompt your favorite AI agent. However, if you feel the strong, human desire to read and to learn from expert humans in their field then this documentation page may be of interest to you.
